# 实验三 B 臂搜索策略审计报告

- 日期：2026-11-06 10:30
- 审计对象：results/exp3_diagnosis.json（6 次运行 × 10 轮完整轨迹）
- 审计方法：轨迹逐轮复盘 + 工具返回重建（CPU 直读 safetensors）+ 投影使用统计
- 起因：用户要求"检查是否可以改进 B 臂的搜索策略"

## 一、审计发现（按证据强度排序）

### 发现 1：投影固着是系统性的——6/6 运行 × 54 调用全部只查 q_proj

```
A0: {'q_proj': 9}   A1: {'q_proj': 9}   A2: {'q_proj': 9}
B0: {'q_proj': 9}   B1: {'q_proj': 9}   B2: {'q_proj': 9}
```

模型在 60 个工具调用机会里**从未轮换投影**。病灶在 up_proj（zero_rows=512
的指纹清晰可见），距离被查询的 q_proj 仅一个字段之遥。

### 发现 2：B 臂清单的"逐投影"指令被执行了它的反义

策略清单第 2 条明写 "For EACH projection type (q/k/v/o/gate/up/down)"。
模型执行了清单**最后一条**（"prioritize mid-to-late layers 18-35"）而完全
忽略第 2 条。这是典型的**末项服从**（recency/last-item bias）：
指令越长，模型抓住结尾细节、丢掉开头要求。

### 发现 3：q_proj 的返回表里没有任何"该换投影了"的信号

重建 B 臂 round 1 收到的 36 行统计表：所有层 mean/std/zero_rows 全部正常
（q_proj 确实干净）。**一张全零异常的表不告诉模型"你查错投影了"**——
从模型视角，"没发现异常"既可能是"这里没问题"也可能是"该去别处看"，
没有信息区分二者。工具协议缺少**覆盖度反馈**。

### 发现 4：B 臂 rounds 2-4 有 3 次近重复调用（预算浪费 30%）

round 2/3/4 都是 compare(q_proj, 18-36)。轻微退化循环：模型在"没看到
异常"时倾向重查而非换维度。但因三次调用的层列表相同，等于烧掉 3 轮。

### 发现 5（排除项）：工具本身工作正常——之前的怀疑不成立

我最初怀疑 device_map 磁盘卸载导致工具在实验中报 meta tensor 错
（审计重放时确实报错了）。核查轨迹：6 次运行 **0 个 tool error**。
重放报错是因为审计时 GPU 被其它进程占用、模型加载落入不同的卸载布局。
实验三的工具返回是真实的。结论"模型没利用 zero_rows"成立。

### 发现 6：off-by-one——模型查询层 1-36（实际 0-35）

list_layers 返回 `num_hidden_layers = 36`，模型理解成"层编号 1..36"。
L0 从未被 B 臂扫描（本实验病灶不在 L0，无实害，但是协议缺陷）。

## 二、根因综合

把发现叠起来，B 臂失败不是单一原因，是**信息架构三重缺陷**：

| 层 | 缺陷 | 证据 |
|---|---|---|
| 工具层 | 一次调用只覆盖 1/7 投影 → 252 单元需 7+ 轮才扫完一列 | 发现 1 |
| 反馈层 | "无异常"结果不含覆盖度状态，模型无从知道该转向 | 发现 3 |
| 指令层 | 长清单的中间条目被忽略（末项服从） | 发现 2 |

推论：**这不是模型"不会"，而是 harness 让"会"变得不可表达**——
10 轮预算下任何策略都无法同时满足"扫全 7 投影 + 验证 + 提案"，
模型（无论 A/B 臂）实际处于策略不可行域。
B 臂的 3/3 区间命中证明：给对指令顺序，层维度策略立刻生效。

## 三、B2 臂改进设计（数据驱动，逐项对应根因）

### 改进 1（对工具层）：`compare_all_projections` 聚合工具

一次调用返回全部 7 投影 × 36 层的异常摘要矩阵（每格：zero_rows +
z-score 摘要）。**一次调用覆盖 100% 搜索空间**（替代 10 轮 4%）。
成本：返回 ~250 行文本，约 8K 字符，远在上下文容量内。

### 改进 2（对反馈层）：覆盖度账本

每次工具返回末尾附加：
`[coverage] projections queried: q_proj(36L); NOT yet: k,v,o,gate,up,down`
把"你还剩什么没看"从模型的记忆负担变成 harness 的显示状态。

### 改进 3（对指令层）：清单重排 + 关键指令置顶置尾

- 把"必须轮换全部 7 种投影"放在清单**第一条**并在**最后一条重复**
  （利用末项服从：结尾放 coverage 检查，"propose 前确认 7 投影都看过"）
- 修正 off-by-one：list_layers 显式返回 `valid_layer_indices: 0-35`

### 改进 4（对重复浪费）：重复调用拦截

harness 检测到与上轮完全相同的调用时返回
"duplicate call — same result as last round; use this round differently"
（不扣预算的警告 + 扣预算的硬拦截各测一版）

### 预注册判定（B2 vs B）

- 主判据：投影正确率（查询或提案指向 up_proj）B2 ≥ 2/3 而 B = 0/3
- 次判据：张量级命中（(层,投影) 二元组正确）B2 ≥ 1/3
- 预算效率：达到首次投影命中的轮次（预期 B2 ≤ 3 轮）

## 四、研究定位修正（由审计触发）

### 4.1 定位转移：从"模型能力测量"到"能力-工具协同设计"

Phase 2 实验三的原定位是测量"模型的自诊策略能力"。审计证明在
JSON-only + 10 轮协议下，该问题**对 4B 模型不可测**（策略不可行域）。
有意义的科学问题是分层的：

- L 层（本审计）：harness 的信息架构如何决定自诊可行性？
  ——可测，且已有三重缺陷的因果证据
- M 层（B2 实验）：给定可行 harness，4B 模型能执行多复杂的策略？
- H 层（Phase 3）：策略执行能力是否随自我改进世代提升？

这直接对接 WSP 原文的隐含立场（Astra 的成功全程带着精心设计的
Python harness）和 Honnibal 批评的深层点：**"模型能力"与"工具环境"
不可分离**。我们的贡献变成：给"自诊可行性"一个信息论式的刻画
（搜索空间 × 预算 × 工具带宽 → 可行域），并用受控实验验证。

### 4.2 与 RSI 主线的关系

RSI 链条 = 自诊 → 定位 → 修复。Phase 2 已证：
- 修复值生成 ≈ 随机（A2 实验）——最深瓶颈
- 定位受限于 harness 而非模型（本审计）——**可修复的瓶颈**
- 行为冗余使缺陷本身无行为后果——但注意：定位实验不需要行为后果，
  zero_rows 指纹就足够。**"统计指纹修复"可以独立于"行为修复"成立**

因此 Phase 3 的 RSI 检验可以降级到可测形态：
**V_k 能否在固定 harness 下逐代提升"指纹定位准确率"**
（不依赖行为缺陷存在性——绕开 Phase 2 S1' 负结果的死结）

## 五、修改后的实验方案

### 实验 3b（B2 臂验证，先行）：工具升级 + 覆盖账本 + 清单重排

- 实现 compare_all_projections 工具（CPU 直读版，绕开 GPU 占用）
- B2 臂 × 3 重复，缺陷不变（cascade3），预注册判定见 §三
- 通过 → 进入 Phase 3；不通过 → 4B 执行能力也成瓶颈，Phase 3 改测
  更小搜索空间（单投影内层定位）的世代提升

### Phase 3 修改稿（替换 RESEARCH_POSITIONING_REVIEW §4 的通道设计）

世代链 V0→V1→V2 的自变量从"权重编辑"改为双通道并行：
- **上下文通道**：V_k 携带自身历史诊断 transcript（对照 C2）
- **权重通道**：V_{k+1} = V_k + 通过 B2 协议定位的指纹修复（A2 式，
  但修复目标是"恢复统计指纹"而非行为——oracle = V0 原值）
- 测量：每代 10 个新鲜缺陷实例上的定位准确率/预算效率
- RSI 判定：通道斜率 > 0（逐代提升）且显著优于 C1 冻结对照
- 诚实条款：若两通道都不升，4B 规模 RSI 不成立的结论收场
