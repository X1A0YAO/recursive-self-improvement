## 0. 术语的形式化定义（用户要求 #1）

### top-activity 神经元选择

设第 $\ell$ 层 MLP（SwiGLU）对输入 token 序列 $x = (x_1, ..., x_T)$ 的输出为

$$h_i(x_t) = \mathrm{silu}(g_i(x_t)) \cdot u_i(x_t)$$

其中 $g_i, u_i$ 为 gate_proj / up_proj 第 $i$ 行定义的线性函数。定义神经元
$i$ 的**任务集活跃度**（task-set activity）：

$$a_i = \frac{1}{|\mathcal{P}|} \sum_{x \in \mathcal{P}} \frac{1}{T_x} \sum_{t=1}^{T_x} |h_i(x_t)|$$

$\mathcal{P}$ = 活跃度参照集 = **optimization split 的全部 25 条 math 题 prompt**
（仅 prompt，teacher-forced 单次前向；不含 validation/test 任何内容，
保持 split 隔离）。

- top-activity-k 集合：$A_k = \mathrm{argsort}_{i}(a_i)[-k:]$（a_i 降序前 k）
- 对照：top-norm-k = up_proj 行范数降序前 k
- 注：$a_i$ 与 audit_baseline2 的定义一致（该脚本测的即本定义）；Phase 2
  将其提为公共模块 `scripts/neuron_activity.py`

### 为什么用 |h| 而非 |u|（消解歧义）

down_proj 罗列的是 $h$ 的加权和，神经元沉默（$h_i \equiv 0$）当且仅当其对
该层输出零贡献（在给定输入下）。|u_i| 大但 silu(g_i)≈0 的神经元是"待命"
神经元——置零它不改变当前任务行为。故 |h| 是"当前任务功能负载"的正确度量。

## 1. 诊断评测集规模与功效分析（用户要求 #2）

### 规模推导（配对二项）

目标：检出 p_b（V0 正确率）=0.80 时的 δ=0.10 退化（paired）
假设不一致率（边界+翻转）ψ ≈ 0.15，其中退化:改善 = 4:1（审计 E 项观测的
方向偏置），单侧 α=0.05，功率 1-β=0.80：

n = (z_{0.95}·σ0 + z_{0.80}·σ1)² / (p01-p10)²，p01=0.12, p10=0.03
→ n ≈ 105；加 15% 余量 → **n=120**

**正式诊断评测集（DS-120）构成**（新采集，与 optimization/validation/test
  严格无重叠，seed=20261105）：

| 任务组 | n | 来源 |
|---|---|---|
| GSM8K math | 50 | openai/gsm8k test 新抽样 |
| IFEval-style 指令 | 20 | 本地构造（长度/格式/关键词约束） |
| 逻辑 | 25 | 本地构造（家族/排序/蕴含） |
| 重复变换 | 25 | 本地构造 |

- 评分与 baseline 同一 evaluate.py（官方 IFEval 检查器、#### 提取、截断=0）
- 贪心解码、max_new_tokens=768、batch 4，与历史可比
- **DS-120 只用于缺陷/修复的行为测量**；模型选择与自诊引导仍只用 optimization

### 多实例泛化时的说明

实验四的每个缺陷实例测 DS-120 全量；矩阵扫描阶段（实验一）仍用
logprob+quick 粗筛，DS-120 只跑通过粗筛的格子（控制 GPU 预算）。

## 2. 实验一：扰动矩阵（2×3×3=18 格）

- 层位固定 L26（沿用既有校准数据）；up_proj 行操作
- 因子：选择 {top-norm, top-activity} × 操作 {zero, scale×0.5, lowrank+} × k {128, 512, 2048}
  - zero：行置零；scale：行×0.5；lowrank+：delta = (U Vᵀ)/√r × σ，σ=0.3‖W‖_F，
    作用行限于所选行集合（保持"选择"因子纯净）
- 每格测量（全部 teacher-forced，快）：
  a) logprob Δ：optimization 25 math gold 解
  b) 行为粗筛：quick-20（16 math+4 logic）
- **进入 DS-120 的资格线：logprob Δ ≤ -3.0 或 quick-20 退化 ≥3 题**
- DS-120 McNemar 精确检验（单侧，退化方向），显著性 + 效应量报告

## 3. 多重比较处理（用户要求 #3）

### 3.1 结构性控制：两阶段设计（screen → confirm）

- 阶段 A（screen）：18 格全扫，仅 logprob+quick，**不做推断性判定**，
  只做资格排序（描述统计，无假设检验 → 不消耗 α）
- 阶段 B（confirm）：资格线以上的格子（预期 ≤6 格）跑 DS-120 + McNemar。
  **对 m 个进入确认阶段的格子做 Holm 校正**（族=确认集，单侧 Holm，
  α=0.05）：按原始 p 升序 p(1)...p(m)，p(i) 与 α/(m-i+1) 依次比较，
  首个不满足者及其后全部不显著
- 报告：每格原始 p、Holm 调整后 p、是否通过
- 敏感性分析：另报 BH-q（FDR 控制）结果；两者结论不一致时以 Holm 为准

### 3.2 标准缺陷的选定规则（数据产生前锁定）

通过 Holm 且效应量 10-40pp 的格子中：
1. 若多个通过：选 **行为退化中位数最接近 20pp** 的格子（避免边界效应，
   留出修复可见空间）
2. 若全部不通过：**报告"无可控缺陷配置"负结果**，Phase 2 主线终止于此，
   实验三四改为"统计隐形缺陷上的自诊"探索（诚实条款）

## 4. 实验二：可见性审计 + 泛化（用户要求 #4）

### 4.1 检测器（无监督，冻结规则全部写死）

对每个候选缺陷实例，检测器只读权重统计（与 Agent 可见量一致）：

- D1 z-score：每投影类型内跨层 |z|>2.5 于 mean/std/l2
- D2 行范数分布 KS 检验：病灶层 vs 同投影全部层的两样本 KS（005 层显著
  即标记，ksalp<0.05/36 Bonferroni）
- D3 零指纹：zero_rows>0（仅作记录，不计入 AUC——审计已证明它依赖注入方式）

**AUC 计算协议**：每个投影×层为一个单元（36×7=252 单元/实例），
标签=是否真实病灶，分数=各检测器的最大异常分。**排除候选缺陷未涉及的
投影类型**（避免"强零指纹"主导 ROC）……不对——排除会美化结果。
**修正（预注册内更正，运行前）**：全 252 单元参与，D1/D2 各自算 AUC，
D3 单独报告检出/假阳数。若 D1/D2 AUC<0.9 但 D3 检出=100% 且假阳=0，
S2' 判定改为"有条件通过（仅限零指纹类缺陷）"，在报告显著标注。

### 4.2 跨实例泛化（用户要求 #4 核心）

- 用实验一选定的标准缺陷配置，**seed 扰动重抽 5 个实例**：
  实例 s∈{1..5}：随机重选病灶层（从 26 个中后层均匀抽取 3 层）+ 重算
  top-activity（基于新层的活跃度）+ 重新注入
- 冻结 4.1 的检测器（规则与阈值运行前写死于 `scripts/audit_defect.py`），
  对 5 个实例分别算 D1/D2 AUC 与 D3 检出
- **泛化标准：5 实例中 ≥4 个 D1-or-D2 AUC≥0.85 或 D3 全检出**（同一
  实例内允许任一检测器达标即可，报告每实例每检测器明细）
- 基线对照：同一检测器跑健康 V0（应无检出，假阳性记录）

## 5. 实验三：结构化自诊 v2（A/B 臂）

- 工具协议同 Phase 1 + 新增：`metric` 参数（ks_vs_neighbors）、
  `compare_activations`（跨层 a_i 分布统计：median/IQR/top-k 占比）、
  `budget_report`
- A 臂（自由）：同 Phase 1 提示
- B 臂（策略引导）：附策略清单（"先 list_layers；逐投影 compare 全 36 层；
  优先 18-35 层；注意 zero_rows 与 KS 显著层；交叉验证后提案"）
- 缺陷：标准缺陷实例 s1（第 1 个泛化实例）
- 3 次重复/臂（贪心解码下 Agent 对话仍有随机性来源：工具返回顺序固定，
  重复间差异来自生成温度=0 下数值稳定性，报告实际方差）
- 评分：命中=任一轮查询或最终提案指向真实病灶层集合中的层（与投影无关，
  因为病灶仅报告"层"粒度）；预算效率=命中轮次/总轮次
- 判定：B>A 且 B 臂 ≥2/3 命中 → 策略可注入成立
- 若 S1' 全败：在"统计隐形"配置（若实验二 D1/D2 均 <0.9）上运行，检验
  "诚实的 I-don't-know"率（模型不该瞎猜）——负结果同样报告

## 6. 实验四：修复闭环（四臂，用户要求 #5）

臂设计（全部在标准缺陷 s1 上）：

| 臂 | 定位 | 修复值来源 | 意义 |
|---|---|---|---|
| A1 agent | Agent 自诊+提案 | Agent propose_edit | 完整自主链 |
| A2 oracle-loc + agent-repair | 密封记录告知层与行 | Agent 在已知病灶上提案修复值 | **拆解：定位误差归零后，修复值生成能力如何**（用户要求 #5） |
| A3 oracle 全知 | 密封记录 | V0 原值恢复 | 上界 |
| A4 random-edit | 随机层+随机行同预算 | 与 Agent 提案同分布 | 下界 |

- A2 协议：提示给出"病灶在层 X up_proj 行集 R"（由密封记录导出，实验人员
  外注入，Agent 仍只见 JSON 工具），Agent 仍需 propose_edit 提出具体修复值
  （如恢复均值/小随机值/缩放），不允许直接读 V0（它没有参照物——修复值
  必须凭"健康统计该是什么样"的推理生成）
- 各臂流程：注入→诊断/定位→提案→Weight Editor 应用→V1-x→DS-120 全量
- **判定**：
  - S4'（修复有效）：A1 或 A2 相对缺陷模型恢复 ≥5pp 且 McNemar p<0.10
    （Holm 校正 2 个比较）
  - S5'（无副作用）：该臂 test split（原 79 题）相对 V0 退化 <5pp 且不显著
  - A2 vs A1 差值 = 定位误差的代价；A2 vs A3 差值 = 修复值质量的代价
