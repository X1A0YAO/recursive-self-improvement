- 日期：2026-11-06 12:00（运行前锁定）
- 依据：用户 Phase 3 设计 + B1/B2a/B2b 三轮实验的全部取证结论
- 范围：本预注册只覆盖实验一（原始权重观察）与实验二（自主诊断）。
  实验三（编辑）、四（递归）在前两实验完成后**另行预注册**（AMENDMENT）。
- 纪律延续：密封盲诊、贪心解码、评分只读最终提案、预注册判定不事后放宽

## 0. 与 Phase 2 的设计差异（核心声明）

Phase 2 的工具**替模型总结**（聚合摘要/统计表）；Phase 3 的工具
**让模型自己看**（原始参数块、自主决定读取位置与范围）。
B2b 教训正式写入 harness 原则：

> **给信息带宽，不给行为处方**——工具提供原始信息与覆盖状态，
> 不在提示里规定模型的搜索/停止行为。

## 1. 技术前提验证（先行，gate）

**Gate-1（mmap 安全）**：read_weight 必须绕开 Windows 跨进程 mmap
冲突（已三次复现 0xC0000005）。方案：工具服务器进程在 GPU 加载前
将所需张量**预载入 RAM**（dict[name->tensor]），运行期零 mmap。
验证：GPU 进程 + 工具进程并行存活 10 分钟无崩溃。

**Gate-2（上下文预算）**：read_weight 单次返回 ≤ 2400 个 float
（约 8K tokens）。4B 模型 32K 上下文 → 单轮诊断会话最多 ~12 次读取。
预算定为 **12 轮**（与 B 系列的 10 轮可比 + 2 轮余量）。

**Gate-3（模型能否读懂数字）**：冒烟测试——给模型一个 64x64 的
真实权重块 + 同张量另一块，问"哪块更异常"（一块注入了已知扰动）。
若 3 次中 0 次答对，实验一降级为"读取行为测量"（不测语义理解）。

## 2. 工具协议（G1/G2/G3 共用，G0 无新工具）

```json
list_tensors()                          // 名称/形状/参数量分区概览（元数据，无数值）
read_weight(tensor, row_start, rows)    // 原始 float 块（≤2400 floats/次）
  // 行=神经元（up_proj 行空间），rows≤8 且 8*hidden≤2400
compare_weights(tensor, ckpt_a, ckpt_b, row_start, rows)
  // 同名张量在两个 checkpoint 的并排原始块（自诊断核心工具）
```

- 返回格式：每行 16 个 float（%.4e），行号标注，块头给 shape/dtype
- compare_weights 的 ckpt 参数在实验二里由 harness 限定为
  {self, healthy_ref}——模型知道"另一个是健康参照"，不知道哪个是哪个的缺陷位置

## 3. 实验一：原始权重观察（Weight Inspection）

**问题**：4B 模型能否有意义地自主读取原始参数（而非统计摘要）？

### 设计

- 对象：V0 健康模型（无缺陷，纯观察能力测量）
- **G1 固定顺序臂**：提示给出固定读取计划（L0-L3 逐层逐投影示例块）
- **G2 自主探索臂**：只给工具书+任务（"自由检查你的权重，汇报发现"），
  零策略指令（B2b 教训：不处方）
- 各 3 次重复
- 测量（全部描述性，本实验不设通过/失败线——能力测绘性质）：
  - 读取多样性：不同张量数/总读取数；层×投影覆盖网格
  - 读取结构性：连续块 vs 跳读；是否用 row_start 做二分/扫描
  - 汇报质量（人工评分 0-2）：观察陈述是否有数据支撑（如"第 5 层
    数值比第 30 层小"是否真在读过的块里成立）
- Gate-3 未过时：只报告读取行为，不做语义判断

### 判定

无 pass/fail（测绘）。产出：G1 vs G2 的读取模式差异 + 供实验二
选用的默认读取预算。

## 4. 实验二：自主缺陷诊断（Self-Diagnosis）

**问题**：原始权重访问（G1/G2/G3）相对统计摘要（G0）能否提升
缺陷定位——尤其对**无零指纹**的缺陷？

### 缺陷实例池（6 个，预生成密封）

| id | 类型 | 层 | 投影 | 指纹 | Phase 2 数据 |
|---|---|---|---|---|---|
| D1 | zero 512 行 | 22,28,30 | up | 零行（硬） | cascade3 已有 |
| D2 | scale 0.5×512 行 | 30 | up | 无零行 | activity_scale_512_L30 已有 |
| D3 | lowrank +30% | 19 | up | 无 | norm_lowrank_128_L19 改造 |
| D4 | zero 128 行 | 19 | up | 零行（硬） | norm_zero_128_L19 已有 |
| D5 | scale 0.5×512 行 | 8 | up | 无零行 | 新注入（浅层对照） |
| D6 | 健康对照 | — | — | 无 | V0 |

- D5 新注入按现有 inject_defect_p2.py 流程 + 密封记录
- 每个 G 臂 × 每实例 1 次（6 臂-实例组合 × 4 组 = 24 次会话），
  预算 12 轮
- **评分（只读最终 propose_edit）**：
  - 层命中率：提案层 ∩ 真层 ≠ ∅
  - 投影命中率：提案投影 = up_proj
  - 张量精确率：(层,投影) ∈ 真值集合
  - 误报率：提案中非真值张量数 / 提案张量数
  - 读取效率：达到首次正确张量读取的轮次（探索性指标）

### 预注册判定

| # | 标准 | 阈值 |
|---|---|---|
| P1 | G2 在无指纹缺陷（D2/D3/D5）上的张量精确率 | ≥2/3（G0 在 Phase 2 为 0/3） |
| P2 | G2 vs G0 在 D1（有指纹）上的张量精确率 | G2 ≥ G0 |
| P3 | G2 误报率 | ≤0.5 |
| P4 | G1 vs G2 读取效率 | 描述性对比（不设线） |
| P5 | Gate-3 语义测试 | ≥1/3 答对（否则实验一降级已在 §1 声明） |

失败条款：P1 未达 → "原始权重访问在 4B 规模不提升无指纹缺陷定位"
作为结论如实报告；不追加臂、不改阈值。

### G3（+前向功能探测）的延迟启动

G3 需要前向 pass 工具（activation_probe 升级版），GPU 排队成本高。
**只在 P1 通过后运行**（预注册顺序），若 P1 失败 G3 不启动。
